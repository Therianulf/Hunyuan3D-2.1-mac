# Deviations from requirements.txt, and why:
#
#   numpy 1.24.4 -> 1.26.4    1.24.4 predates solid cp311 wheel coverage for the
#                             rest of this stack. Must stay <2.0: basicsr and
#                             realesrgan break on the numpy 2.x ABI.
#   onnxruntime 1.16.3 -> 1.19.2   1.16.3 has no cp311 Windows wheel.
#   pymeshlab unpinned        2022.2.post3 has no cp311 Windows wheel.
#   open3d unpinned           Let pip resolve the current cp311 win_amd64 build.
#
#   DROPPED cupy-cuda12x      Never imported anywhere in the repo (verified by
#                             grep). ~500MB of install for nothing.
#   DROPPED deepspeed         Never imported on the inference path, and it has no
#                             supported Windows build.
#   DROPPED bpy==4.0          Wheels exist only for Python 3.10, and it is only
#                             needed by the standalone blender_*.py scripts.
#                             mesh_utils.py already falls back to driving an
#                             external Blender executable when bpy is absent.
#   DROPPED pythreejs         Jupyter-only visualisation widget, never imported.
#
#   open3d is also never imported anywhere in this repo (grepped for both
#   `open3d` and `o3d`). It is ~400MB and can be dropped outright if you want a
#   leaner env; it is kept here only so this file stays a faithful analogue of
#   requirements.txt.
#
#   The two --extra-index-url mirrors from requirements.txt (Tencent Cloud and
#   Aliyun) are omitted -- they are slow or unreachable outside mainland China
#   and pip will fall through to PyPI anyway.
#
# xatlas IS required here (uvwrap_utils.py) even though requirements-macos.txt
# commented it out -- it has working Windows wheels.
